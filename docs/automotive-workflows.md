# 汽车零件设计：如何组织曲面操作

汽车外覆盖件、内外饰件和许多钣金件确实高度依赖曲面；但安装支架、转向/制动零件、壳体、连接件等仍大量依赖实体特征、装配约束和工程图。因此，本包把曲面放在优先位置，而不是删去其他功能。

## 推荐的设计顺序

| 阶段 | 可用工具方向 | 人工/工程检查 |
|---|---|---|
| 基准准备 | 点、样条、偏置平面、几何图形集 | 单位、车身坐标系、左右侧、截面顺序、输入数据来源 |
| 主曲面 | Hub loft/fill/connect；daiemon sweep/revolve/extrude | 引导线是否相交、法向、接缝位置、扭曲、自交 |
| 修整 | project/intersection/split/trim/offset | 选择保留侧，偏置方向，局部小半径导致的失败 |
| 接合 | join/heal/boundary | 公差是否满足设计要求，开口/非流形边界是否符合意图 |
| 转实体 | thick_surface/close_surface | 厚度方向、体积、薄壁失败、实际设计壁厚 |
| 结构细节 | Pad/Pocket/孔/圆角/阵列等 | 无效切除、干涉、安装尺寸、脱模和工艺要求 |
| 输出 | 参数检查、工程图、受控保存/导出 | 单位、公差、数据版本与下游交换格式 |

建议把输入曲线、基准、主曲面、修剪结果分别放入命名清晰的几何图形集。保证对象名唯一；名称查找不等于长期稳定拓扑引用。边索引在模型更新之后可能变化，圆角等操作必须重新检查。

## 三类优先验证的样件

1. **等厚内饰/饰板局部件**：截面样条 → 带引导线 loft → trim → join → thick_surface → 安装孔/局部圆角。
2. **钣金支架的几何原型**：基准面/曲线 → extrude/sweep → trim/offset → join → 加厚。这里只生成几何，不替代专门钣金展开、回弹或冲压仿真。
3. **导管/护罩局部件**：多截面/扫掠 → 过渡/填充 → 拼接检查 → 厚度 → 开口与接口特征。

优先从局部件和已有设计副本开始，不把“整车自然语言建模”作为首个验收目标。

## 工具选择示例

- `hub__catia_create_loft` 支持有序截面、引导线、截面方向和 coupling 参数。
- `hub__catia_create_fill` 接受边界、支持面和连续性请求。
- `daiemon__catia_gsd_offset_surface` / `catia_gsd_trim` / `catia_gsd_split` 补充常用曲面修剪能力。
- `hub__catia_join_surfaces` 提供距离/角度公差与连接、流形选项。
- `hub__catia_check_surface_quality` 更新并测量对象、查询部分连接设置和最小间距；**不是完整 A 级曲面质量分析**。
- `hub__catia_thick_surface` 把命名曲面转成有方向的厚实体。

上面省略了统一前缀的第二次重复写法时，仍需以 `auto_catalog`/MCP 工具列表中的完整工具名为准。

## 受控组合而不是盲目批处理

`auto_surface_pipeline` 的步骤为 `{ "tool": "完整工具名", "arguments": {...} }`，只接受受控曲面工具，在同一 STA 中按序执行。每步失败即停止并保留已发生的修改证据；**它不是原子事务，也不承诺整批回滚**。首次实机验收应拆成单步执行，确认后再组合。

每次使用前执行 `auto_bind_document`，通过 schema 提交 `document_token` 和修改操作的 `request_id`。只使用当前 token；成功修改后跟随 `next_document_token`。从 MCP `tools/list` 取到实际 schema（`auto_catalog` 返回来源/状态摘要），再填业务参数，不照抄不明来源的旧 JSON。

## 特别警惕的“看起来成功”

- 设置 G2 只是创建参数；必须用 CATIA 的曲率/反射线等专业分析另行检查。
- Join 的 connex/manifold 模式不是所有形状都已被证明符合该性质。
- Pocket 无体积变化应视为无效特征，而不是有效切除。
- 测量存在单位、对象类别和算法局限；未验证单位的距离与近似包围盒不可作验收尺寸。
- 生成截图不等于几何正确；截图请求尺寸也不代表真实输出像素。
- Analysis Compute 返回，不等于求解收敛、网格合格或结果具备物理意义。
