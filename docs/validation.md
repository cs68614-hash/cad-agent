# 验证范围与首次实机验收

## 不混淆三种验证

1. **静态检查**：解析 Python/JSON、检查注册表、源代码来源与禁用原因；不能证明代码可运行。
2. **离线测试**：mock、请求日志、文档控制、路径与协议行为；不能证明 COM API、几何、许可、求解有效。
3. **实机验收**：Windows + 具体 CATIA V5 release + 工作台许可 + 可丢弃样件，记录结果与失败截图。此交付不能替代该步骤。

测试状态以交付时验证记录为准；没有执行的测试必须标为未运行，不以“提供测试脚本”冒充已通过。

## 离线命令

```bash
PYTHONPATH=src python -m unittest discover -s tests -v
```

真实协议测试要验证 MCP initialize、tools/list、tools/call、isError 与 structuredContent，以及 HTTP 的错误 token、Host、Origin 拒绝。模拟源工具只证明连接到了相应分发路径，不能算每个几何工具的 COM mock 单测覆盖。

## 实机检查清单（必须另行授权）

在专用 Windows 用户会话中，CATIA 已启动；退出其他自动化程序，关闭有价值的文档，使用工作目录内副本。记录 CATIA release/SP/HF、Python/pywin32/MCP 版本、工作台许可、用户权限、文件目录。

- [ ] 只连接已运行 CATIA，不静默启动第二个实例。
- [ ] 校对活动文档，绑定后切换文档，确认原 token 不会误改另一文档。
- [ ] 用 10 mm 简单基准块检查长度、面积、体积、坐标与单位。
- [ ] 创建两条截面和引导线，loft/fill → trim → join → 厚度；检查对象树和几何。
- [ ] 测试失败偏置、无效 Pocket、无效对象名，检查是否部分修改、是否报告错误。
- [ ] 更新后重新取得边引用，验证圆角，不重复利用旧边索引。
- [ ] 检查请求 ID 重放、变更参数冲突、token 过期与服务重启行为。
- [ ] 在可控样件上模拟超时，等待 COM 返回后人工检查，再执行未知结果恢复确认。
- [ ] 目录外打开/导出/材料路径以及隐式 Save 必须拒绝。
- [ ] 验证 STEP/IGES 导出、非空文件、必要时重导入和几何检查。
- [ ] 工程图、装配和 Analysis 分模块验收，不以曲面通过代替全部通过。
- [ ] Analysis 另行验证材料引用、实体属性、约束/载荷、网格、收敛和结果；没有闭环证据不得用于工程签核。

`scripts/live_validate.py` 只生成可填写的实机验收记录模板，不连接 CATIA、不修改模型。它要求显式 `--i-understand-live-catia`，防止被误认成自动离线验证。真正实机操作应在批准后，逐项通过 MCP 执行并填入证据。
